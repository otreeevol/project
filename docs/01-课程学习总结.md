# 一、课程学习总结

## 1. 软件工程核心概念

软件工程是以系统化、规范化、可度量的方法应用于软件的开发、运行和维护的学科，其核心目标是在预算、时间和质量约束下交付满足用户需求的高质量软件产品。

课程系统讲解了软件生命周期的阶段性划分（需求分析、设计、编码、测试、运维），软件开发模型包括：

- **瀑布模型**（文档驱动）：强调阶段划分严格、文档齐备，适合需求稳定的大型项目；
- **原型模型**：通过快速构建可交互原型来澄清需求，适合需求模糊的场景；
- **迭代模型 / 增量模型**（增量理念）：把系统拆分为多个增量，逐步交付、逐步完善；
- **螺旋模型**（风险控制）：在迭代基础上引入风险评估，适合大型、高风险项目；
- **敏捷方法**：以人为核心、快速迭代、响应变化，适合需求快速变化的互联网产品开发；
- **群智开发方法**：依托开源社区众包协作，如小米便签所在的 MiCode 开源社区。

此外课程还介绍了软件生命周期内的过程控制、方法与 CASE 工具，开源软件许可证与开源软件平台，以及 AI 大模型在软件工程（如代码生成、测试用例生成、需求分析辅助）中的应用。

## 2. 软件工程方法学

### 2.1 软件需求工程

**结构化软件需求分析**：采用层次模型与数据流图（DFD）自顶向下、逐步求精地刻画系统的数据加工过程。

**面向对象的需求分析**：采用 UML（统一建模语言）对系统进行建模，通过用例图、类图、顺序图、状态图等视图从不同侧面描述系统需求。

### 2.2 需求分析

软件需求模型以 UML 为核心：

- **用例图、类图**：描述系统功能与领域对象；
- **顺序图（交互图）**：描述用例之间的消息传递；
- **状态图**：描述软件运行过程中对象的状态转移。

需求分析还需进行**文档化**（编写软件需求规格说明书 SRS），并开展**需求验证、确认和文档评审**，确保需求正确、完整、一致、无歧义。

### 2.3 软件设计

软件设计的过程为：

> 体系结构设计 → 用户界面（UI）设计 → 详细设计 → 编码 → 设计文档 → 评审

软件设计的基本原则包括：

- 抽象与逐步求精；
- 模块化：高内聚、低耦合、信息隐藏；
- 多视点与关注点分离；
- 软件重用；
- 迭代设计；
- 可追踪性。

### 2.4 体系结构设计

常见的分层体系结构为**三层架构**：

- **表示层**（界面）：负责与用户交互；
- **应用（业务）层**：实现核心业务逻辑；
- **数据（服务）层**：负责数据持久化与访问；
- 此外还可划分出**基础设施层**提供通用服务。

常用的设计模式/架构风格：分层、管道-过滤器、黑板、MVC、SOA、消息总线。

体系结构设计模型：包图、构件图、部署图；设计元素包括子系统、构件、类及其消息接口；并文档化为**软件总体设计方案**。

### 2.5 用户界面设计、详细设计与编码实现

- **用户界面设计（§9）**：遵循易用性、一致性、反馈及时等原则设计交互界面。
- **详细设计（§10）**：在总体设计基础上，用类图、顺序图、活动图等精化每个模块的内部结构与算法。
- **编码实现（§11-12）**：遵循编程规范，注重注释、代码优化与异常处理。

### 2.6 测试、部署、运维与项目管理

- **测试（§13）**：单元测试 → 集成测试 → 系统测试 → 验收测试，并编写测试计划与测试用例；
- **部署（§14）**：规划基础设施、运行平台、构件安装位置与外部服务接口；
- **运维（§15）**：系统上线后的运行监控、维护与持续改进；
- **项目管理（§16）**：范围、进度、成本、质量、风险与团队管理，配合 Git 等版本控制工具实施配置管理。

## 3. 学习收获

通过本课程与项目实践，我掌握了以 UML 为核心的面向对象需求分析与设计方法，理解了从需求到设计、编码、测试、部署的完整软件生命周期；并在从零开发「学生信息管理系统」的过程中，把课堂理论（三层架构、高内聚低耦合、数据访问层封装、版本控制等）与真实工程实践相结合，加深了对软件工程方法论的理解。
