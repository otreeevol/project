## 1. 测试计划

### 1.1 测试目标

验证小米便签各功能模块是否满足需求规格说明，发现并记录缺陷，评估系统质量。

### 1.2 测试范围与策略

| 测试类型 | 测试内容 | 依据 |
| --- | --- | --- |
| 单元测试 | `Note`、`WorkingNote`、`NotesProvider` 等关键模块的方法级验证 | 详细设计 |
| 集成测试 | 模块间接口调用（UI → WorkingNote → Provider → SQLite） | 总体设计 |
| 系统测试 | 基于需求规格说明验证整体功能 | SRS |
| 验收测试 | 由用户执行，确认是否满足业务需求 | SRS 验收要求 |
| 性能/压力测试 | 大量便签下的列表加载、滚动与并发写入 | 非功能需求 |

### 1.3 测试环境

- 设备：Android 真机 / 模拟器（API 14+）；
- 工具：JUnit、AndroidJUnitRunner、Monkey（随机压力测试）。

## 2. 测试用例设计

### 2.1 单元测试用例

| 用例编号 | 模块 | 输入 | 预期输出 |
| --- | --- | --- | --- |
| UT-01 | `Note` | 从 Cursor 加载一条记录 | 各字段（snippet、type、id）正确赋值 |
| UT-02 | `WorkingNote.saveNote()` | 空文本 | 返回 false，不写入数据库 |
| UT-03 | `WorkingNote.saveNote()` | 非空文本 | 返回 true，`note`/`data` 表写入成功 |
| UT-04 | `NotesProvider.insert()` | 非法 URI | 抛出 `IllegalArgumentException` |
| UT-05 | `NotesProvider.query()` | 按 `_id` 查询 | 返回对应 Cursor |

### 2.2 集成测试用例

| 用例编号 | 接口 | 输入 | 预期输出 |
| --- | --- | --- | --- |
| IT-01 | UI → WorkingNote → Provider | 在编辑页保存新便签 | 列表页出现该便签 |
| IT-02 | Provider → SQLite | 删除某文件夹 | 该文件夹下便签级联删除 |
| IT-03 | GTaskManager → Provider | 触发同步 | 本地与云端数据一致 |

### 2.3 系统测试用例

| 用例编号 | 功能 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ST-01 | 新建便签 | 点击新建 → 输入 → 保存 | 便签出现在列表 |
| ST-02 | 编辑便签 | 点击便签 → 修改 → 保存 | 内容更新 |
| ST-03 | 删除便签 | 长按 → 删除 | 便签移入回收站 |
| ST-04 | 搜索 | 输入关键字 | 返回匹配便签 |
| ST-05 | 文件夹 | 新建文件夹并移动便签 | 便签归类正确 |
| ST-06 | 提醒 | 设置提醒时间 | 到期弹出提醒 |
| ST-07 | 小部件 | 添加到桌面 | 桌面显示便签内容 |

### 2.4 性能/压力测试

- 预置 1000 条便签，测试列表加载时间与滚动流畅度；
- 使用 Monkey 随机操作 30 分钟，观察崩溃与 ANR 情况。

### 3.1 主要缺陷与处理

| 缺陷编号 | 描述 | 严重程度 | 状态 |
| --- | --- | --- | --- |
| BUG-01 | 便签删除后 `notes_count` 未及时刷新（触发器遗漏场景） | 中 | 已修复 |
| BUG-02 | 无网络时云同步出现未捕获异常 | 低 | 已修复（增加异常处理） |

## 4. 测试结论

经过单元、集成、系统与性能测试，小米便签的核心功能（便签增删改查、文件夹管理、提醒、小部件、同步）均满足需求规格说明书要求，缺陷均已修复并回归通过，具备部署上线条件。
