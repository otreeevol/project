## 1. 测试计划

### 1.1 测试目标

验证学生信息管理系统各功能模块是否满足需求规格说明，发现并记录缺陷，评估系统质量。

### 1.2 测试范围与策略

| 测试类型 | 测试内容 | 依据 |
| --- | --- | --- |
| 单元测试 | DAO 层与 Service 层的方法级验证 | 详细设计 |
| 集成测试 | 控制器 → Service → DAO → SQLite 的完整链路 | 总体设计 |
| 系统测试 | 基于需求规格说明验证整体功能 | SRS |
| 验收测试 | 由用户执行，确认是否满足业务需求 | SRS 验收要求 |

### 1.3 测试环境

- 运行环境：Python 3.11 + Flask 2.2 + SQLite；
- 测试框架：`unittest` + Flask `test_client`；
- 测试代码：`src/tests/`（test_dao.py、test_service.py、test_app.py）。

## 2. 测试用例设计与结果

### 2.1 单元测试（DAO 层）

| 用例 | 输入 | 预期输出 | 结果 |
| --- | --- | --- | --- |
| 班级创建/查询 | 新增班级后 list_all | 返回 1 条班级记录 | ✅ 通过 |
| 班级更新/删除 | 修改班主任后删除 | 数据更新、删除后为空 | ✅ 通过 |
| 学生创建/查询/列表 | 新增学生后 get/list_all | 字段正确、含班级名 | ✅ 通过 |
| 学生搜索 | 按"王小明"/学号搜索 | 命中相应学生 | ✅ 通过 |
| 删除级联 | 删除有成绩的学生 | 其成绩一并删除 | ✅ 通过 |
| 成绩统计 | 录入 80、40 两条成绩 | 平均 60、及格率 50% | ✅ 通过 |

### 2.2 单元测试（Service 层）

| 用例 | 输入 | 预期输出 | 结果 |
| --- | --- | --- | --- |
| 登录成功 | admin / admin123 | 返回 admin 用户 | ✅ 通过 |
| 登录失败 | 错误密码 | 抛出 AuthError | ✅ 通过 |
| 重复用户名 | 再次创建 admin | 抛出 ValueError | ✅ 通过 |
| 新增学生 | 合法数据 | 成功写入 | ✅ 通过 |
| 缺少必填 | 空学号/姓名 | 抛出 ValueError | ✅ 通过 |
| 学号重复 | 重复学号 | 抛出 ValueError | ✅ 通过 |
| 成绩越界 | score=120 | 抛出 ValueError | ✅ 通过 |
| 成绩合法 | score=88 | 统计平均分 88 | ✅ 通过 |

### 2.3 集成测试（Flask 应用）

| 用例 | 操作 | 预期输出 | 结果 |
| --- | --- | --- | --- |
| 未登录拦截 | 直接访问 /students/ | 302 重定向到登录页 | ✅ 通过 |
| 登录成功 | 提交正确账号 | 进入首页（系统概览） | ✅ 通过 |

| 成绩非法值 | 提交 score=150 | 提示"成绩必须在 0~100 之间" | ✅ 通过 |

## 4. 测试结论

经过单元测试、集成测试与系统级验证，学生信息管理系统的登录、学生/班级/课程管理、成绩录入与统计等功能均满足需求规格说明书要求，输入校验与异常处理完备，未发现阻塞性缺陷，具备部署上线条件。
